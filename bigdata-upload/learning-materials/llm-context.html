什么是 LLM Context？

把大模型的"上下文窗口"理解成你此刻能记住的
一切——大脑的短期记忆与 LLM 的"工作台"

一句话定义
Context（上下文）是 LLM 在一次对话中能"看见"的所有内容，包括系统提示、用户输入、对话历史、工具返回值等所有塞进输入窗口的文本。

💡个人解释：用"短期记忆"类比

把你和 LLM 的对话想象成跟一个记忆力只有几秒的朋友协作：

🧠 人类短期记忆

容量有限（约 7±2 项），只能装"此刻你正在想的事"。一旦走神，前面的对话就"忘掉"了——必须别人复述一遍才能想起来。

🤖 LLM 的 Context 窗口

容量以"token"计量（GPT-4o 约 128k，Claude 3.5 约 200k）。窗口外的旧内容不是被"压缩"，而是从未被 LLM 看见。

关键相似：两者都不是"长期仓库"，都是当前这一次思考能用到的工作台。

关键差异：人是主动忘（注意力转移），LLM 是被动忘（窗口满了会截断更早的内容），但效果很相似——LLM 不知道被截掉的那段发生过。

⚙️核心机制

Context 的工作原理三件事：

① 拼接 → ② 切分 token → ③ 注意力计算

一个 Context 窗口内部大致长这样：
系统
用户历史
工具返回
本轮问题
系统提示（角色 / 规则） 对话消息（用户 + AI） 工具结果 / RAG 召回

三大要点：

1. 窗口有上限：超出后被截断而非压缩；LLM 此时对被截断内容完全无感知。

2. 窗口内一切可见：所有被塞进去的 token 都会被注意力机制读到，互相影响。

3. 顺序有讲究：开头和结尾的内容（"首因 / 近因效应"）对模型影响最强，中间的内容容易"被忽略"。

Context 是 LLM 此刻的全部世界——世界之外，它一无所知。

🌍具体应用场景

  • 多轮对话：把前面所有轮的消息都塞进 Context，AI 才能"记得"你之前说过什么
  • RAG（检索增强生成）：先把你的问题去向量数据库检索，再把检索到的相关文档片段塞进 Context
  • 工具调用 / Function Calling：工具的返回值塞回 Context，让模型能基于真实数据继续推理
  • 长文档摘要：把整篇论文 / 合同塞进 Context，让模型基于全文总结
  • Few-shot 提示：在 Context 里塞几个示例，让模型"看着例子学"然后再回答
  • 系统提示（System Prompt）：把角色设定、风格、禁忌都写在 Context 开头，约束后续输出

⚠️易混淆点 / 边界

❓ Context ≠ 训练数据
训练数据是毕业前学的知识，Context 是当下摆桌上的资料。二者混淆会导致你期待"它应该知道"，但它其实从没在你这次对话里看到。
❓ Context Window 越大越好吗？
不绝对。窗口越大，推理成本↑、响应速度↓、"中间被忽略"的现象越明显。GPT-4o 的 128k 和 Claude 的 200k 各有取舍，盲目塞满常常比精挑细选效果更差。
❓ Context 和 Memory 是一回事？
不是。Context 是每次请求都重新构造的输入；Memory 是跨会话持久化的外部存储（向量库 / 摘要库 / 数据库）。AI 在新会话里"记得"你，是因为开发者把 Memory 又塞进了 Context。
❓ 为什么 AI 会"忘记"对话开头的内容？
通常是窗口溢出被截断（最常见），或注意力衰减（距离当前位置太远，注意力权重变小）。修复思路：把关键信息挪到末尾、缩减对话、定期摘要压缩。
