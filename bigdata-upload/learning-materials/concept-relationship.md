# Concept Relationship：Agent、Skill 与 LLM Context 的关系说明

## 一、核心关系类比

用"大脑、工具箱与工作台"来理解三者的关系：

- Agent（大脑）：负责决策和调度，判断当前该做什么、下一步怎么走。
- Skill（工具箱）：封装好的具体能力，Agent 需要时才调用，平时不占用注意力。
- Context（工作台）：决定了 Agent 此刻能看到什么信息，是它推理和判断的边界。

> 工作进行中，大脑（Agent）不断从工具箱（Skill）中取出合适的工具，放到工作台（Context）上，再基于工作台上现有的信息决定下一步行动。

---

## 二、概念对比表

| 概念 | 类比角色 | 核心作用 | 对任务的影响 |
| :--- | :--- | :--- | :--- |
| Agent | 大脑 | 拆解任务、逻辑推理、决定调用哪个 Skill | 决定任务的方向 |
| Skill | 工具箱 | 封装具体的执行能力，如搜索、写代码、查数据 | 决定任务的可行性 |
| Context | 工作台 | 承载当前可见的所有信息，是 Agent 推理的依据 | 决定任务的复杂度上限 |

---

## 三、重点说明

### 上下文如何影响 Agent 的工作

Context 是 Agent 的短期记忆和注意力范围。

- 视野限制：Context 窗口越小，Agent 能看到的背景信息越少。哪怕 Skill 再强大，如果 Context 里看不到相关线索，就无法正确调用。
- 信噪比：Context 里塞入的信息越多，Agent 越容易分心。清理 Context，本质上就是在帮 Agent 集中注意力。
- 动态变化：随着对话推进，旧信息被挤出、新信息加入。Agent 必须在有限空间内维持任务的连续性。

### Skill 如何沉淀可复用的任务知识

Skill 本质上是"被压缩的经验"。

- 流程封装：没有 Skill 时，每一步操作都要写进 Prompt 塞进 Context，既浪费空间又容易出错。有了 Skill，复杂流程被封装成一个调用，Agent 只需知道"用哪个"，不需要记住细节。
- 解耦与标准化：Skill 将领域知识从 Agent 的通用逻辑中剥离出来。业务规则变了，只需更新 Skill，不用动 Agent 本身。
- 跨场景复用：一个写好的 Skill 可以被多个 Agent 调用，实现一次编写、处处复用。
