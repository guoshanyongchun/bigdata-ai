# Concept Learner · 通用概念学习资料生成器

一个**通用、主题无关**的学习工具。给它一个概念名，它就产出对应的入门资料；适用于任何学科、任何领域、任何学习阶段。

---

## 一、适用场景

在以下任一情况触发本 Skill：

- 用户给出概念名（"帮我做一份 XX 的学习资料"），意图是**入门理解**而不是查字典
- 用户在课程 / 书中遇到陌生概念，需要快速建立初步认知
- 用户希望把零散知识沉淀为结构化笔记 / 卡片 / 速记
- 用户给出一组概念，希望批量产出体系化的概念地图

**不适用**：

- 单纯查询定义（一句话回答即可，无需生成文件）
- 深入原理、公式推导、生产级代码示例（那是另一类长笔记）
- 非概念类诉求（例如改 bug、操作某软件）

---

## 二、输入信息

调用本 Skill 前，从用户消息中提取或询问以下信息：

| 字段 | 必填 | 默认 | 说明 |
|------|------|------|------|
| **概念名** | ✅ | — | 本次要学习的概念（中英文均可） |
| **所属领域** | ❌ | 自动推断 | 例如 大数据 / 机器学习 / 后端 / 通用 / 人文 |
| **目标受众** | ❌ | "入门/零基础" | 入门 / 进阶 / 高级，会改写段落深度 |
| **学习目标** | ❌ | "理解是什么 + 与易混淆概念的差别" | 例如"入门并厘清与 XX 的区别" |
| **输出格式** | ❌ | Markdown 学习卡片 | Markdown / HTML（独立单页）/ PDF / 飞书文档 |
| **文件命名** | ❌ | `<concept>.md` | 用户未指定时用小写英文 + 中划线 |
| **存放目录** | ❌ | 工作目录下 `notes/concepts/` 或 `learning-materials/concepts/` | 已存在的优先；都不存在则询问 |
| **学习日期** | ❌ | 今天（`date` 命令获取） | ISO 格式 `YYYY-MM-DD` |

> **核心逻辑**：本 Skill 不预置任何概念内容，每次调用都把"概念名"当成全新输入处理。它是一个**生成器**，不是一个固定答案库。

---

## 三、生成步骤

按顺序执行：

### Step 1 — 确认输入

- 从用户消息中提取"概念名"等关键字段
- 必填项缺失则**主动询问**（一次问完，不要挤牙膏）
- 推断领域时若拿不准，就在生成稿子里同时给"通用"和"该领域"两个视角，避免猜错

### Step 2 — 检索 / 验证（必要时）

- 概念在训练知识内 → 直接落笔
- 概念超出训练知识 / 时效性强（如新框架、新版本）→ 用 `WebSearch` 检索
- **优先级**：官方文档 > Wikipedia > 知名技术博客 > 教科书
- 必要时 `WebFetch` 拉取权威页面验证

### Step 3 — 按受众深度生成正文

根据"目标受众"控制语言密度：

| 受众 | 段落深度 |
|------|----------|
| **入门 / 零基础** | 用生活类比，避免术语；需要时可标注"延伸阅读" |
| **进阶** | 增加技术细节 / API / 适用条件；类比可有可无 |
| **高级** | 直接进入原理、权衡、对比；不必铺垫入门解释 |

### Step 4 — 选择输出位置

优先级：

1. 当前工作目录下 `notes/concepts/`（若已存在）
2. 当前工作目录下 `learning-materials/concepts/`（若已存在）
3. 用户显式指定的路径
4. 询问用户

若目标文件已存在，询问用户**覆盖 / 加时间戳后缀 / 跳过**。

### Step 5 — 写入并展示

- Markdown / HTML 文件用 `Write` 工具一次性写入完整内容
- 文件末尾注明"延伸阅读"提示，建立概念间关联
- 用 `present_files` 把产出呈现给用户预览（HTML 同时打开浏览器预览）
- 若生成了概念卡片系列，更新所在项目的 `MEMORY.md` 加入系列总览

---

## 四、输出结构

每份资料**至少**包含以下 6 个段落（Markdown / HTML 都适用）：

| # | 段落 | 写法 |
|---|------|------|
| 1 | **一句话定义** | ≤30 字，精准不含糊；推荐句式"X 是一种 Y，用于 Z" |
| 2 | **直觉理解** | 2-3 句日常类比，让目标受众秒懂；入门必给，进阶可省 |
| 3 | **为什么需要它** | 解决什么具体痛点；不用会怎样；相对替代方案的优势 |
| 4 | **核心区别 / 对照分析** | 用对比表或并列段落，重点厘清与**易混淆概念**的差异（用户常指定此项） |
| 5 | **示例 / 案例** | 给一个能跑通的最短场景，能用伪代码或生活场景就避免真代码 |
| 6 | **延伸阅读 / 学习路径** | 标注 3-6 个相关概念（`→` 串联），并视情况加"当前你在这里"标记 |

### Markdown 模板

```markdown
# {概念名}

> 学习日期: {YYYY-MM-DD} | 领域: {领域} | 受众: {受众}
> 标签: #{tag1} #{tag2}

## 一句话定义
{≤30 字定义}

## 直觉理解
{类比，2-3 句}

## 为什么需要它
{痛点 + 解决思路}

## 核心区别 / 对照分析
| 维度 | A | B |
|------|---|---|
| ... | ... | ... |

## 示例
{最短可跑场景}

## 延伸阅读
{A → B → C}

---
**生成器**: Concept Learner · 本卡片由通用概念学习资料生成器产出
```

### HTML 卡片附加约定

当输出格式为 HTML 时：

- **单文件自包含**：所有 CSS 内嵌，不引外部资源，断网也能看
- **顶部 hero**：渐变色块 + 标题 + 副标题 + emoji 行
- **段落卡片化**：每段用独立 `<section class="card">`，圆角 + 阴影
- **系列化配色**：连续产出多张卡片时，每张换一个主色（蓝紫 / teal / 暖橙 / 玫红轮换），方便视觉区分
- **底部导航**：若是系列第 N 期，注明"上一期 → / 下一期 →"互相串联

---

## 五、资料来源要求

- **可验证**：所有事实性陈述必须能在权威来源追溯
- **可标注**：概念名、版本号、专有名词与用户消息原文保持一致，不要"智能改写"
- **不要编造**：对超出训练知识的内容，必须检索后再写；检索不到的明确标注"未验证"
- **引用优先级**：官方文档 > Wikipedia > 知名技术博客 > 教科书 > 二手社区帖
- **避免过时**：时效敏感的概念（框架版本、价格、监管）必须用 `WebSearch` 更新到当前时间

---

## 六、自检要求

写完一份资料后，**生成器自己**做一遍这 6 项检查；任一项不过就重写那一段：

- [ ] **受众匹配**：术语密度符合"目标受众"档位（零基础不出现未解释的术语）
- [ ] **一句话定义 ≤30 字**，且句式可套"X 是一种 Y，用于 Z"
- [ ] **直觉类比**真的来自目标受众熟悉的生活场景（程序员类比只对程序员友好）
- [ ] **核心区别**真的回答了用户最想厘清的那个混淆点（不是泛泛而谈）
- [ ] **示例**能在零代码环境下被一个普通人理解
- [ ] **延伸阅读**概念之间有真实的逻辑递进关系，不是凑数

---

## 七、迭代建议

- 入门卡片积累到 10+ 张时，可在模板追加字段：核心原理 / 代码示例 / 易混淆概念 / 面试常问
- **追加而非删除**旧字段，保留学习轨迹
- 卡片之间用 `→` 或 `[[概念名]]` 串联，逐步形成个人知识网络
- 批量场景：一次多个概念时，逐个调用本 Skill、复用同一套标签体系

---

_本 Skill 主题无关：下次调用只需换"概念名"输入，其余流程不变。_
